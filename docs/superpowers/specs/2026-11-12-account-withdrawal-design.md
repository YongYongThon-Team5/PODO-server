# 회원탈퇴 설계

작성일: 2026-11-12 · 상태: 사용자 승인 완료 (2026-11-13) · 담당: SeokH-dev

## 1. 목적과 범위

[Figma 마이페이지](https://www.figma.com/design/lWZGGaQay5Wcp7wKw6YEze/?node-id=209-256)의 회원탈퇴 버튼을 실제 서버 동작으로 연결한다. 현재 서버 `00297d0`에는 로그아웃은 있지만 회원탈퇴 API가 없다. 기존 인증과 프로필 파트 작성자인 사용자 담당으로 진행한다. 다른 파트 변경 검토 PR #14·#15와 독립된 신규 기능이다.

사용자와 정한 기준:

- 요청 접수 즉시 계정 이용을 차단하고 모든 로그인 세션을 폐기한다.
- 아이 프로필, 방문·답변·힌트 기록, 관찰 사진, 개인 생성 퀴즈 및 프로필 사진을 모두 삭제한다.
- 공용 장소·출처·공용 퀴즈와 다른 계정의 데이터는 보존한다.
- 카카오 연결도 해제한다. 일시적인 외부 장애는 서버가 재시도한다.
- 모든 처리가 끝날 때까지 같은 카카오 계정의 재가입을 막고, 완료 뒤에는 새 계정으로 가입할 수 있다.
- 데모는 Figma에 있는 기능을 기준으로 한다. 탈퇴 현황 대시보드·알림·계정 복구·관리자 API는 추가하지 않는다.

이 문서는 요구·구조·검증 기준이며 구현 완료를 의미하지 않는다. 아래 경로·테이블 이름·재시도 간격은 작성자의 구현 제안이다. 이 문서 승인 뒤 구현 계획에서 파일과 테스트 단위로 나눈다.

## 2. 검토한 방식

| 방식 | 동작과 제약 | 선택 |
|---|---|---|
| 요청 한 번에 외부 연결 해제와 삭제 완료 | 작지만 카카오 지연 때 응답이 길어지고 외부 성공/DB 실패 복구가 어려움 | 제외 |
| 영속 탈퇴 작업 | 즉시 차단 후 카카오·파일·DB 정리를 단계별 재시도. 재시작 후에도 이어갈 수 있음 | 사용자 선택 |
| 로컬 계정만 삭제 | 카카오 연결이 남음 | 사용자 요구에 맞지 않아 제외 |

외부 서비스와 로컬 DB를 하나의 트랜잭션으로 묶지 않는다. 계정은 마지막까지 `WITHDRAWING` 상태로 남겨 동일 카카오 subject의 재가입을 차단한다.

## 3. API와 화면 연결

제안: `DELETE /api/me`, 본문·쿼리 없음.

- 기존 로그아웃과 같은 Bearer, 정확한 Origin, 세션에 연결된 CSRF 검증을 적용한다. Refresh 쿠키가 있으면 현재 Bearer와의 세션 불일치를 차단하는 기존 규칙을 따른다.
- 인증 계정으로만 탈퇴한다. 요청 본문에 accountId나 카카오 subject를 받지 않는다.
- 접수 트랜잭션 완료 시 `202 Accepted`, 응답 예시 `{"status":"PROCESSING"}`. Refresh·CSRF 쿠키를 지우고 `Cache-Control: no-store`를 적용한다.
- 프론트는 메모리 토큰·개인 API 캐시·사진 object URL을 비우고 기존 로그인 화면으로 돌아간다. 기존 메시지 영역에 “탈퇴 요청을 접수했어요. 처리가 끝날 때까지 다시 가입할 수 없어요.”를 표시한다. 202를 삭제 완료로 안내하지 않는다.
- 일반 네트워크 오류는 접수 성공으로 간주하지 않는다. 응답 유실 뒤 인증이 만료되면 재로그인 경로에서 처리 중 여부를 판별한다. 기존 무효 토큰을 계속 허용하는 탈퇴 전용 인증 예외를 만들지 않는다.
- 접수 후 같은 토큰의 반복 호출은 401일 수 있다. DB 작업은 계정당 하나만 생성하고 작업자 재시도는 멱등하게 처리한다. HTTP 요청마다 반드시 같은 202를 준다고 약속하지 않는다.
- 처리 중 재로그인은 기존 OAuth 실패 콜백에 `ACCOUNT_WITHDRAWING` 같은 고정 오류 코드를 전달하는 안을 사용한다. 클라이언트가 임의 리다이렉트 URL을 지정하지 못하게 한다. 상세 오류 코드 이름은 구현 계획에서 기존 enum과 맞춘다.
- 카카오 Admin Key 등 필수 서버 설정이 아예 없으면 변경 전에 503으로 거절한다. 설정이 존재하지만 공급자 장애인 경우는 접수 후 재시도한다. 키 미설정 상태에서 성공처럼 보이는 데모를 만들지 않는다.

## 4. 접수와 인증 경합

여기서 즉시 차단은 접수 트랜잭션이 커밋된 뒤 새 인증·쓰기를 차단한다는 뜻이다. 이미 전송 중인 HTTP 응답이나 외부 AI 호출을 강제로 취소한다는 보장은 아니다.

한 DB 트랜잭션에서 계정 행 잠금 → ACTIVE 확인 → WITHDRAWING 전환 → 전 세션·토큰 폐기 → 유일한 탈퇴 작업 생성을 수행한다. 트랜잭션 실패 시 어떤 단계도 부분 반영하지 않는다.

현재 `AuthSessionService.issueForKakaoSubject`는 insertIfAbsent 후 일반 조회, refresh는 세션을 먼저 잠그고 계정을 일반 조회한다. 탈퇴를 추가할 때 로그인·refresh·로그아웃도 **계정 → 세션** 순서로 잠금을 일치시키고, 잠금 후 최신 ACTIVE 상태를 확인하도록 보완한다. 계정 식별용 사전 읽기는 허용하되 유효성 최종 판단은 잠금 뒤에 한다. 새 세션이 생기거나 토큰이 다시 발급되는 경쟁을 테스트한다.

현재 개인 쓰기·관찰 생성 결과 저장은 계정 잠금과 ACTIVE 검사를 사용하는 경로가 있다. 각 쓰기 경로를 모두 점검해 인증 필터 통과 이후 탈퇴와 경합해도 커밋 시점에 개인 데이터가 다시 생기지 않도록 한다. 개인 읽기도 이미 인증된 요청과 삭제가 겹칠 수 있으므로 읽기 실패를 내부 오류나 타 계정 데이터 노출로 바꾸지 않는다.

## 5. 영속 작업과 완료 조건

제안 테이블 `account_withdrawals`: account_id 유일, 진행 단계, 처리 점유 토큰/만료 시각, 재시도 시각·횟수, 분류된 오류 코드. 민감한 원문 오류나 사진·키를 저장하지 않는다. 작업은 DB에서 영속 관리하고 서버 재시작 뒤 재개한다. 여러 인스턴스는 짧은 트랜잭션으로 작업을 점유하고 토큰으로 구 작업자의 결과 반영을 차단한다.

작업 순서:

1. **카카오 연결 해제:** 서버만 보유한 Admin Key와 계정의 subject로 요청한다. 외부 호출 동안 DB 잠금을 잡지 않는다. 성공 확인 후 단계 완료를 저장한다.
2. **파일 삭제 목록 확보와 개인 DB 정리:** 계정·방문을 일관된 순서로 잠그고 개인 퀴즈·사진의 범위를 확정한다. 실제 파일 경로를 영속 삭제 작업에 먼저 기록한 뒤 개인 DB 참조를 제거한다. 같은 트랜잭션에서 수행해 파일 정리 정보 유실을 막는다. 계정은 아직 삭제하지 않는다.
3. **파일 정리:** 프로필 이미지와 관찰 이미지 파일을 삭제한다. 없는 파일은 완료로 처리한다. 실패는 다음 시각에 재시도한다. 중복 키를 한 번만 처리하고 다른 계정이 사용하는 파일을 지우지 않는다.
4. **최종 완료:** unlink 확인·개인 DB 정리·모든 파일 삭제 완료를 확인하고 계정, 탈퇴 작업, 완료된 개인 파일 작업의 식별 정보를 삭제한다. 이 최종 트랜잭션이 완료된 뒤에만 재가입할 수 있다. 영구적으로 카카오 subject나 개인 기록을 남기는 tombstone은 만들지 않는다.

재시도 제안은 지수 증가 간격과 최대 간격 30분이다. 일시적 실패에 임의의 횟수 상한으로 작업을 유실하지 않는다. 잘못된 인증/설정은 운영 로그의 분류 코드로 드러내고 설정이 수정된 뒤 재개할 수 있게 한다. 이력 보존 기간 같은 제품 외 정책은 새 기능으로 추가하지 않는다.

카카오 타임아웃은 연결 해제 실패 확정이 아니다. 외부 성공 직후 DB 기록 전에 중단되는 경우를 포함해 재호출과 이미 해제된 상태의 판정을 설계한다. 특정 카카오 오류를 성공으로 간주하려면 공식 의미와 해당 앱·사용자 대상이 확인되어야 한다. 임의 4xx 전체를 성공 처리하지 않는다. 이 세부 오류 매핑은 공식 계약 테스트를 만드는 구현자에게 맡기되, 성공을 입증하지 못한 작업은 최종 삭제 완료로 전환하지 않는다.

## 6. 삭제 범위와 순서

현재 스키마에는 `visits.quiz_set_id → quiz_sets.observation_id → observations.visit_id` 순환과 문항의 사진 FK가 있다. 계정 DELETE나 무조건 CASCADE로 끝내지 않는다.

계정에 연결된 방문·관찰·개인 세트를 먼저 수집하고 아래 순서를 적용한다. 정확한 SQL은 실제 FK를 다시 확인해 작성한다.

1. 프로필/관찰 파일의 삭제 작업을 영속 저장한다. observations의 기존 첫 사진 컬럼과 observation_images 모두 고려한다.
2. 해당 방문의 현재 세트 참조를 해제한다. 방문의 답안·힌트 기록을 제거한다.
3. 해당 관찰에 속한 개인 문항·퀴즈 세트를 제거한다. 공용 세트나 공용 출처를 삭제하지 않는다.
4. 관찰 이미지 행 → 관찰 → 방문 순으로 제거한다.
5. 프로필과 해당 계정의 이미지 메타데이터, 인증 토큰·세션·계정에 연결된 OAuth 요청 등을 제거한다.
6. 파일 정리와 최종 완료까지 계정의 WITHDRAWING 상태는 유지한다.

프로필 사진 하나를 같은 계정의 여러 프로필이 공유할 수 있으므로 중복 삭제에 견딘다. 기존 프로필 이미지 삭제 큐를 재사용할지 공통 파일 작업으로 묶을지는 구현자 선택으로 두되, 계정 제거로 파일 삭제 경로가 같이 사라져서는 안 된다.

진행 중 AI 작업은 결과 저장 시 ACTIVE·방문 상태·점유 토큰을 재검증해야 한다. 탈퇴 이후 완료한 모델 호출이 새 퀴즈를 저장하거나 실패 처리로 관찰을 복구하지 못하게 한다. 작업자가 이미 읽은 파일 바이트가 있을 수 있으므로 외부 호출 취소와 결과 DB 반영 차단을 같은 것으로 취급하지 않는다. 기존 파일 조회·정리 작업과 동시 접근 시 안전한 없는 파일 처리를 유지한다.

삭제 대상은 서비스가 관리하는 DB와 파일 저장소다. 이미 전송한 외부 AI 처리 데이터나 백업·플랫폼 로그까지 이 API가 즉시 삭제했다고 표현하지 않는다. 새 구현이 개인 데이터 원문을 로그에 남기지 않게 한다.

## 7. 카카오 연결과 설정

현재 카카오 access token은 로그인 사용자 확인에 일시 사용하고 보관하지 않는다. 따라서 탈퇴 작업은 [공식 연결 해제 API](https://developers.kakao.com/docs/ko/kakaologin/rest-api#unlink)의 Admin Key 방식을 사용한다. 이 키의 실제 발급·권한·환경 설정은 구현 전 별도 확인한다. 값은 문서·PR·클라이언트에 넣지 않는다.

연결 해제는 외부 요청이므로 현재 로그인 REST 키·Client Secret이 있다는 사실만으로 실행 가능하다고 간주하지 않는다. 실환경 검증은 삭제를 허용한 테스트 계정으로만 수행하고, 스텁 통과와 실제 연결 해제 증거를 구분한다.

## 8. 검증 기준

| ID | 시나리오 | 성공 기준 |
|---|---|---|
| W-01 | 정상 접수 | 202, 쿠키 제거, 계정 차단·전 세션 폐기·영속 작업이 함께 커밋 |
| W-02 | 잘못된 인증/Origin/CSRF·다른 세션 조합 | 개인 데이터와 계정 상태에 변경 없음 |
| W-03 | 접수 DB 실패·중복 요청·응답 유실 | 부분 차단/작업 유실 없음, 계정당 작업 하나, 무효 인증 우회 없음 |
| W-04 | 두 기기에서 로그인·refresh·탈퇴 경합 | 탈퇴 접수 이후 새 유효 세션/토큰이 남지 않고 교착 없이 완료 |
| W-05 | 프로필·방문 생성/수정·사진 업로드와 경합 | 탈퇴 뒤 새 개인 데이터가 남지 않음 |
| W-06 | AI 생성 중 탈퇴 | 구 작업자가 개인 퀴즈/관찰 상태를 다시 저장하지 못함 |
| W-07 | 카카오 지연·5xx·잘못된 키·이미 해제 | 분류된 재시도, 불확실한 응답을 성공 처리하지 않음 |
| W-08 | 외부 성공 뒤 DB 실패·서버 종료 | 재시작 후 멱등하게 이어가고 재가입 차단 유지 |
| W-09 | 공유 프로필 사진·관찰 구버전 사진·누락 파일 | 계정의 모든 파일 제거, 파일 누락은 성공, 다른 계정 파일 보존 |
| W-10 | 파일 삭제 실패·작업자 중복 점유 | 영속 재시도·구 토큰 결과 차단, 완료 전 계정 유지 |
| W-11 | FK 순환·여러 번 정정한 퀴즈 | 삭제가 FK 오류 없이 완료되고 개인 답안·힌트·세트 잔존 없음 |
| W-12 | 삭제 범위 | 공용 장소/출처/퀴즈와 다른 계정 데이터가 동일하게 유지 |
| W-13 | 처리 중/완료 후 카카오 재로그인 | 처리 중 차단, 완료 뒤 새 UUID 계정·빈 개인 기록 |
| W-14 | 프론트 접수·네트워크 실패 | 접수/완료 구별, 개인 캐시 정리, 실패를 성공으로 안내하지 않음 |

기존 PostgreSQL Testcontainers 인증·관찰 통합 테스트와 HTTP 공급자 스텁을 사용한다. 시간과 재시도는 주입 가능한 시계로 검증한다. 신규 기능 단위 테스트뿐 아니라 기존 refresh·로그아웃·퀴즈 경합 테스트도 실행한다. 외부 키 없는 CI에서는 실제 unlink를 호출하지 않는다.

## 9. 구현 범위 지도

2026-11-13 범위 정정: 본 구현은 서버만 담당한다. 위의 프론트 동작은 API 연동 요구의 설명이며 다른 담당자의 프론트 코드를 수정하지 않는다. 서버 연동 가이드로 전달한다.

- 서버 인증: 계정 상태 전이, DELETE 경계 검증, 전체 세션 폐기, 로그인·refresh 잠금과 처리 중 로그인 결과
- 서버 정리: 새 Flyway 마이그레이션, 영속 작업·파일 정리·FK 순서·worker 경합 처리
- 외부 연동: Admin Key 설정과 unlink 클라이언트·오류 매핑
- 프론트 담당 전달사항(이 브랜치 구현 제외): Figma 마이페이지 탈퇴 버튼 연결, 처리 중 안내, 개인 캐시/사진 정리
- 문서/검증: Swagger, 개발 설정 이름만 문서화, 통합·경합·실환경 증거

기존 기능을 변경하는 인증 경합 작업과 C파트 테이블 삭제 경로는 사용자가 구현하되 해당 파트 계약을 침범하는 변경을 별도 구현 PR에 드러낸다. 다른 팀원 가이드 PR의 미정 정책을 이 설계에서 확정하지 않는다.

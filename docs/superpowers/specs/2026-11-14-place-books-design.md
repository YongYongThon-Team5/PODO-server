# 장소 관련 도서 조회 설계

2026-11-14 · 서버 담당 SeokH-dev · 사용자 지시: 계획을 잡고 바로 구현. 별도 승인 대기 없이 실행한다.

## 범위

[Figma 장소 상세](https://www.figma.com/design/lWZGGaQay5Wcp7wKw6YEze/?node-id=143-1986)의 ‘같이 읽으면 좋은 책’과 용인시 공공도서관 정보를 제공한다. 회원탈퇴 PR #19와 독립된 `origin/dev` 기반 `feature/place-books` 브랜치다. 프론트 코드는 변경하지 않는다.

팀이 장소와 관련된 책을 선정한다는 기존 논의를 따른다. 용인시가 장소별 관련 책을 자동 추천하는 기능은 제공하지 않으므로 임의의 AI 추천·추천 순위를 만들지 않는다.

## 외부 근거와 제한

공식 [용인시 신간도서 API](https://www.data.go.kr/data/15097224/openapi.do)의 `GET https://apis.data.go.kr/4050000/libnewbk/getLibnewbk`를 사용한다. 인증키·pageNo·numOfRows가 필수이며 도서명/저자/출판사 검색이 가능하다. 응답은 도서명·저자·출판사·발행연도·도서관·자료실 등을 제공한다.

2026-11-12 실제 호출에서 조건 없는 목록은 정상, ‘애벌레’는 59건, Figma 예시 ‘배고픈 애벌레’는 검색 결과 없음이었다. 검색 실패를 용인 전체 미소장으로 해석하지 않는다. 오래된 반납 예정일이 포함돼 대출 Y/N의 의미·최신성을 확정하지 못했다. 이번 구현은 대출 가능 여부·반납 예정일·표지·ISBN을 응답하지 않는다. 정보나루 등 다른 공급자를 자동 추가하지 않는다.

## 선택한 접근

- 선정 도서와 제공자 조회를 분리한다. `podo.books.recommendations` 설정에 placeId별 최대 3권의 title/author/publisher/publicationYear를 등록한다. 제공자 데이터에서 복사한 정확한 값을 사용한다. 운영자 관리 API나 도서 테이블·마이그레이션은 만들지 않는다.
- 고정 목록만 표시하면 소장 도서관을 확인할 수 없어 제외했다. 무제한 외부 키워드 검색·AI 선정은 디자인보다 범위가 넓어 제외했다.
- 기본 선정 목록은 빈 배열이다. 실제 장소·책 연결을 추정하거나 테스트 자료를 운영 설정으로 넣지 않는다. 실제 키와 검수한 목록을 설정하면 바로 조회 가능한 API를 제공한다.

## API

`GET /api/places/{placeId}/books` — 기존 공개 장소 정책과 동일. 공개 PUBLISHED 장소만 허용, 미존재/비공개404. 잘못된 UUID·쿼리·본문400. 비로그인 허용, 무효 Bearer가 있으면 기존 필터401.

응답은 200 `items`, `warnings`, `checkedAt`:

```json
{"items":[{"title":"실제 응답 제목","author":"실제 응답 저자","publisher":"실제 응답 출판사","publicationYear":"2024","libraries":[{"name":"실제 응답 도서관","room":"실제 응답 자료실"}]}],"warnings":[],"checkedAt":"2026-11-14T00:00:00Z"}
```

- 선정 도서의 순서를 유지한다. 각각 정확한 서지 4개 필드가 일치하는 행만 합친다. 문자열은 앞뒤/연속 공백만 정리하고 다른 판본이나 비슷한 제목을 임의로 같다고 보지 않는다.
- 도서관·자료실 쌍은 중복을 제거한다. 불완전한 서지·도서관 행은 결과로 주장하지 않는다. 자료실만 없는 경우 room=null로 허용한다.
- 선정된 책이 제공자 결과에 없으면 항목을 만들지 않고 `CURATED_BOOK_NOT_FOUND` 경고. 원래 API의 신간 범위에서 못 찾았다는 뜻이다.
- 미선정은 `NOT_CURATED`, 키/설정 없음은 `PROVIDER_NOT_CONFIGURED`, 제공자 실패는 `PROVIDER_UNAVAILABLE`, 조회 범위 초과는 `RESULTS_TRUNCATED`를 경고 배열로 반환한다. 경고는 중복 없이 고정된 순서로 반환한다.
- 한 도서 조회 실패가 다른 정상 도서 결과를 지우지 않는다. 하나라도 실패하면 실패 경고와 함께 가능한 결과를 반환한다. 전부 실패면 빈 목록과 경고. 공급자 실패를 ‘도서 없음’으로 바꾸지 않는다.
- 응답은 Cache-Control:no-store와 기존 X-Request-Id 관행을 따른다. checkedAt은 우리 서버 확인 시각이며 공급자 데이터 갱신 시각으로 표현하지 않는다.

## 제공자 경계

- 키는 `YONGIN_LIBRARY_API_KEY` 서버 환경변수. 값은 저장소/테스트/로그/응답에 넣지 않는다. 반환 source URL에 인증키 URL을 사용하지 않는다.
- 선정 도서당 첫 페이지100행만 조회한다. 최대3권으로 총 HTTP 요청3회, 요청당 연결2초/응답5초, 자동 재시도 없음. totalCount>100이면 RESULTS_TRUNCATED. 누락된 다음 페이지를 모두 검색했다고 표현하지 않는다.
- 요청 시 키를 한 번만 URL 인코딩한다. 본문은 실제 관측된 flat JSON, 성공 resultCode0/NORMAL_CODE, 빈 결과는 resultcode3/NODATA_ERROR 변형을 지원한다. key 대소문자 차이와 코드 숫자/문자열은 명시적으로 처리한다. 임의 다른 오류는 빈 결과가 아니다.
- HTTP401/403/429/5xx·타임아웃·깨진 JSON·잘못된 페이지/항목 구조는 분류된 공급자 실패. 원본 response body와 예외 cause/전체 URL은 노출하지 않는다. 고정 HTTPS endpoint와 redirect 비활성화.
- 외부 HTTP 호출 중 DB 트랜잭션을 잡지 않는다. 공개 여부 확인은 짧은 저장소 조회로 한다. 설정이 비어 있어도 기존 앱 기동에 영향이 없어야 한다.
- 별도 캐시/배치/다중 공급자 fallback은 이번 데모 범위에 포함하지 않는다. 호출 상한과 제한을 문서에 명시한다.

## 검증과 전달

HTTP 스텁은 실제 관측 flat 응답 형태를 사용하고 비밀값 없는 synthetic 키·도서를 사용한다. 실제 제공자 호출 성공 경험은 코드의 실환경 검증을 대신하지 않는다. 새로 발급된 키를 파일에서 찾거나 대화에 나온 과거 키를 재사용하지 않는다.

공급자 직렬화/인코딩/오류, 일치·불일치·중복·부분실패·미선정, 공개/비공개·인증·본문 검증, Swagger를 테스트한다. Testcontainers로 공개 장소를 검증하며 기존 장소/추천 API는 유지한다. 최종 전체 테스트와 독립 리뷰를 수행하고 프론트 담당자용 서버 연동 문서를 제공한다.

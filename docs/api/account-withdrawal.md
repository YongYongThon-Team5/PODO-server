# 회원탈퇴 API 연동 가이드

서버 연동 계약. 담당: 서버 SeokH-dev. 프론트 코드 변경은 이 브랜치 범위에 포함하지 않는다.

[승인된 설계](../superpowers/specs/2026-11-12-account-withdrawal-design.md) · [구현 계획](../superpowers/plans/2026-11-13-account-withdrawal.md)

## 요청

`DELETE /api/me` — 본문과 쿼리 파라미터 없이 요청한다.

| 값 | 규칙 |
|---|---|
| Authorization | 현재 로그인 세션의 `Bearer <accessToken>` |
| X-CSRF-Token | `GET /api/auth/csrf`에서 받은 현재 세션의 토큰 |
| Origin | 서버에 등록한 정확한 프론트/API 출처. 브라우저가 전송 |
| 쿠키 | CSRF 쿠키 필수. Refresh 쿠키는 선택이며 유효한 쿠키가 있으면 Bearer와 같은 세션이어야 함 |

카카오 계정 ID나 삭제할 사용자 ID를 요청에 넣지 않는다. 로그인한 본인만 탈퇴한다. 요청 전에 프론트 담당자는 계정·아이·탐험 기록·사진이 삭제되고 복구되지 않는다는 점을 사용자에게 안내한다.

## 접수 응답

`202 Accepted`, `Cache-Control: no-store`

```json
{"status":"PROCESSING"}
```

서버는 계정 이용 차단·모든 로그인 세션 폐기·영속 작업 저장을 마친 뒤 응답한다. 202는 모든 파일과 카카오 연결까지 이미 삭제됐다는 뜻이 아니다. Refresh·CSRF 쿠키는 만료된다.

프론트 연동 시 필요한 동작:

1. 202 확인 뒤 메모리 Access/CSRF·개인 API 캐시·사진 미리보기 주소를 정리한다.
2. 로그인 화면의 기존 안내 영역에 접수 사실과 처리 중 재가입 제한을 표시한다.
3. 접수 전에 시작한 토큰 갱신 응답이 늦게 도착해 로그인 상태를 복구하지 못하게 한다.
4. 실패·응답 유실을 탈퇴 완료로 표시하지 않는다. 같은 토큰 재시도는 이미 폐기되어 401일 수 있다.

서버 API만으로 클라이언트 메모리나 이미 전송 중인 응답까지 강제로 삭제하는 것은 아니다. 각 클라이언트의 캐시 정리는 프론트 담당자의 연동 작업이다.

## 처리와 재가입

카카오 연결 해제 → 개인 DB 정리 → 개인 파일 정리 → 최종 계정 삭제 순으로 서버가 진행한다. 타임아웃·저장소 장애 시 작업은 DB에 남아 재시도된다. 처리가 끝나기 전에는 같은 카카오 계정으로 로그인/재가입할 수 없고, 완료 뒤 로그인하면 새 계정으로 가입한다. 기존 기록은 복구하지 않는다.

별도 상태 조회 화면·상태 조회 API·관리자 검수 API는 이번 데모 범위에 포함하지 않는다. V6 이전 사진 삭제 대기열에서 소유자를 복원할 수 없는 항목이 남아 있으면, 잘못된 삭제 완료를 막기 위해 기존 정리 작업이 해당 대기열을 비울 때까지 탈퇴 완료가 보류될 수 있다. 오래된 파일의 저장소 오류나 잘못된 키가 계속되면 관련 데이터·저장소를 운영 측에서 확인해야 한다. 처리 중 검증된 카카오 로그인 콜백은 기존에 설정된 실패 URI로 이동하며 `error=ACCOUNT_WITHDRAWING`을 전달한다. 임의 외부 URL로 이동하지 않는다. 이때 카카오 동의로 앱 연결이 다시 생겼을 수 있으므로 연결 해제를 다시 예약하고 기존 작업 점유권을 무효화한다.

이미 연결 해제 HTTP가 진행 중이었다면 이전 작업의 점유 만료 시각까지 다음 연결 해제를 보류한다. 처리 중 여러 번 재동의해도 이 대기 시간을 줄이지 않는다. 이 기간에는 재가입도 계속 차단된다.

## 오류 대응

| 상황 | 연동 시 처리 |
|---|---|
| 400 `INVALID_REQUEST` | 본문·쿼리·중복 쿠키 등 요청 형식 확인 |
| 401 `AUTHENTICATION_REQUIRED`, `INVALID_TOKEN`, `TOKEN_EXPIRED` 등 | 인증을 다시 확인. 탈퇴가 끝났다는 의미로 사용하지 않음 |
| 403 `CSRF_INVALID` | 정확한 Origin과 현재 세션의 CSRF 쿠키·헤더 조합 확인 |
| 409 `AUTH_CONTEXT_MISMATCH` | 유효한 Refresh와 Bearer가 같은 세션인지 확인 |
| 503 `SERVICE_UNAVAILABLE` | 서버 설정 미준비로 접수 전 거절. 나중에 다시 시도 |
| 네트워크 실패·응답 유실 | 성공/실패를 단정하지 않음. 재로그인 결과와 처리 중 안내로 복구 |

공급자 원문 오류·토큰·카카오 subject는 사용자 응답에 노출하지 않는다.

## 서버 설정과 검증

`KAKAO_ADMIN_KEY`가 별도로 필요하다. 기존 카카오 REST 키·Client Secret과 다르며 앱의 연결 해제 API 호출 권한을 확인한다. 키는 서버 환경변수로만 전달한다. `.env` 원문이나 실제 키를 PR에 첨부하지 않는다.

키 형식과 타이밍 설정이 유효해야 준비 상태다. HTTP 연결·응답 제한은 각각 1ms 이상이고 합이 점유 시간 5분보다 작아야 하며, 확인 주기는 1ms 이상이어야 한다. 잘못된 설정은 기존 로그인 앱의 기동을 막지 않지만 탈퇴 접수는 503으로 거절하고 작업자도 실행하지 않는다. 실제 삭제를 허용한 테스트 계정이 없거나 키가 준비되지 않았다면 HTTP 스텁 검증과 실환경 검증을 구별해서 보고한다.

삭제 대상은 계정의 아이 프로필·인증 세션/토큰·방문·답안·힌트·개인 생성 퀴즈·개인 사진이다. 공용 장소·출처·공용 퀴즈와 다른 계정 데이터는 유지한다.

검증 내역과 구현 중 판단은 [구현 검증 기록](../superpowers/notes/2026-11-14-account-withdrawal-verification.md)을 참고한다.
